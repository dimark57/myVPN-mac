# UX обновления списков RU в menu bar

Дополнение к **doc-4 — Menu bar myVPN** (тело doc-4 сейчас отсутствует, осталась только `.sig`) и к **doc-2 — Ядро sing-box и CLI myvpn** (§ списки RU).  
Задача: **DRAFT-1** — UX обновления списков RU: прогресс и результат.

Цель: при «Обновить списки RU…» пользователь **видит ход и итог**, меню **не глушится целиком**.

## Граница

| Входит | Не входит |
|--------|-----------|
| Индикация прогресса на пункте меню (точки) | Клон Happ (подписки, VLESS, магазин) |
| Два именованных списка RU в UI | Новые источники сверх ru-routing-dat / doc-2 |
| Явный успех / ошибка + last-updated | Network Extension (**doc-5**) |
| Меню остаётся usable во время обновления | Полноценный progress-bar widget / отдельное окно Happ |

## Сколько списков

Ровно **два** набора правил (как сейчас собирает `myvpn update-rules`):

| Имя в UI | Файлы / смысл |
|----------|----------------|
| **geosite-ru** | домены РФ (whitelist / category-ru) → `geosite-ru.srs` |
| **geoip-ru** | IP/CIDR РФ → `geoip-ru.srs` |

Каталог: `~/.config/myvpn/rules/`. Не показывать «десятки подписок Happ».

## Поведение меню (обязательно)

### Не глушить меню

- Пока идёт `update-rules` (или любая долгая команда): **disabled только текущий пункт** (повторный клик запрещён).
- Остальные пункты (Вкл/Выкл, NAS, Настройки, Выход) **остаются доступны**, если сами не конфликтуют по смыслу.
- Нельзя снова выставлять global `busy` на всё меню.

### Прогресс точками

Пока пункт занят, title анимируется кадрами:

```text
.
..
...
..
```

цикл (пример: `Обновить списки RU… .` → `..` → `...` → `..` → `.`).  
Интервал ~0.3–0.4 с. Обновлять **title in-place**, чтобы открытое меню не закрывалось от полного `rebuildMenu`.

Тот же приём допустим для других долгих действий (Вкл/Выкл, NAS, helper), но для списков RU — **обязателен**.

### Состояние в покое

В меню (disabled info-строки или submenu «Списки RU») видно:

1. `geosite-ru` — дата/время mtime файла правил **или** «нет» / «ещё не обновляли».
2. `geoip-ru` — то же.
3. Опционально одна строка «Обновлено: …» = max(mtime) двух файлов.

Источник даты: mtime `~/.config/myvpn/rules/geosite-ru.srs` и `geoip-ru.srs` (или JSON-сиблинги, если srs ещё нет). Не секрет.

### Успех и ошибка

| Исход | UI |
|-------|-----|
| Успех | Уведомление (или явная смена info-строк): «Списки RU обновлены» + время. Пункт снова enabled, точки сняты. |
| Ошибка | Уведомление с кратким stderr/`myvpn` message. Меню не зависает в busy. Info-строки не притворяются успехом. |

Тихий успех **запрещён**.

## CLI (минимум)

`myvpn update-rules` остаётся SoT загрузки (doc-2). Для UI достаточно:

- exit 0 / ≠0;
- при желании — stdout с двумя строками статуса (не обязательно для v0, если UI читает mtime файлов).

Потоковый прогресс процентов **не** требуется: точки на пункте меню достаточны (решение CEO).

## Приёмка

1. Клик «Обновить списки RU…» → на пункте крутятся `.` / `..` / `...` / `..`; остальное меню не серое.
2. После успеха — уведомление или обновлённые даты у geosite-ru и geoip-ru.
3. В покое видно оба списка и когда обновляли (или «нет»).
4. При сбое сети — ошибка понятна, busy снят, меню живо.
5. Нет отдельного окна «как Happ»; нет global mute меню.
